# 参赛准备与项目边界

来源：用户提供的《2026武汉1024·人工智能创新生态系列活动——人工智能创新应用黑客松参赛流程指引》，以及2026-10-17读取的[活动官网](https://wuhan.uoyc.com/1024/hackathon/)。这是参赛准备说明，不代表已报名或已获资格。

## 建议与导师讨论的定位

优先考虑“科研创新”中的实验辅助：帮助研究/开发人员以一致条件测试LLM服务，保存可核对数据，并对异常提出待验证解释。项目名称可沿用“面向大语言模型推理服务的自动化性能评测与分析系统”。不以“已实现自动诊断”“算法领先”为参赛陈述。

## 计划节点

指引列出10月20日前报名组队，10月22日17:00前提交代码仓库或可运行Demo链接及汇报PPT。官网仍说明正式资格、既有项目与单人参赛规则待正式公告，时间及提交渠道需以组委会最终通知为准。

## 当前材料与缺口

| 材料 | 当前状态 | 参赛前要做什么 |
| --- | --- | --- |
| 代码仓库 | 当前项目首次公开快照 | 导师确认赛道与既有项目资格 |
| 真实报告与图表 | 已有，带明确配置与局限 | 选一段可讲清的对照，不堆全部研究记录 |
| 演示 | CLI、CPU测试、真实结果浏览可用 | 录制简短流程；现场GPU演示作为条件选项 |
| 汇报PPT | 本次未制作 | 说明问题、核心功能、实现、应用价值和边界 |
| Web结果浏览/任务管理 | 本地只读浏览器已有；任务执行未接入 | 演示筛选、分位数、原始证据与CSV，不能称在线压测已接入 |
| 科研创新结论 | 未成立 | 区分工程差异化、研究假设和已验证结果 |

近期优先保证“能运行、能展示、数字有来源、评委能理解用户价值”。不为参赛打断现有毕设底座，也不需要先完成论文。报名、团队信息、作品正式提交均由用户决定，本次没有代报名。

# 项目介绍

## 要解决的问题

选择和部署LLM推理服务时，性能数字经常难以比较：模型与精度不同、请求长度不同、预热不同，或者只看一个平均值而忽略失败请求与尾延迟。本项目把实验配置、请求执行、指标采集、数据校验和结果展示放在一个流程中，便于追溯每个数字来自哪里。

## 当前实现

`study.py`负责受控运行，`lab.py`负责客户端压测与结果校验，`tail_report.py`分析请求级延迟。底层调用现有推理引擎及其官方Benchmark客户端，不重写模型推理框架。`research/experiments/`保存为研究问题设计的独立实验脚本。

已经有vLLM/SGLang对比报告、失败请求和配置检查、图表、实验原始件与CPU测试。现新增FastAPI/SQLite只读结果浏览器，可按引擎/并发检索、查看单次运行详情、导出和追溯数据。任务创建、执行状态机与单GPU worker尚待接入，不能称完整管理平台已完成。

## 可以怎样演示

1. 打开固定并发报告，说明模型、硬件、请求长度、重复次数与指标定义。
2. 查看同一报告的PNG/SVG图表及原始JSON，展示数字可追溯。
3. 运行CPU测试，展示错误输入、缺失指标和请求失败会被拒绝。
4. 如现场GPU环境允许，按配置启动单个引擎并执行一组压测；现场条件不足则展示已有真实数据，不把离线演示说成实时推理。

浏览器演示可运行`python -m benchmark_lab`，详见[本地演示](LOCAL_DEMO.md)。

研究部分目前主要验证：额外阶段与资源信息是否能帮助区分相似性能症状。在证明测量可靠之前，不继续开发自动诊断算法。工程成果独立服务于毕设，科研假设即使失败也不影响其基础价值。
